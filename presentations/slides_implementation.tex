\begin{frame}{Implementation}
\framesubtitle{Input data}
\begin{itemize}
    \item Fixed list of keywords (from Google Ads past searches, Semrush).
    \item Google Ads reports
    \begin{itemize}
        \item Keyword-level past performance (daily clicks, costs).
        \item Campaign-level past performance (total clicks, purchases, also broken down by segment).
        \item Historical metrics for each keyword (e.g., search volume).
        \item These are currently manually downloaded, but we would need to automate
        this to download daily (e.g., using Google Ads API).
    \end{itemize}
\end{itemize}
\end{frame}

% ============================================================================
% Slide 2 — Processing Overview
% ============================================================================
\begin{frame}{Implementation}
\framesubtitle{Processing}
The processing pipeline consists of the following stages (currently four separate Python scripts):
\begin{enumerate}
    \item Data processing: combining reports, getting keyword embeddings.
    \item Modeling: fit an XGBoost model to predict clicks.
    \item Optimization: embed model and use Gurobi to solve (maximizing clicks or purchases).
          The model is large and is currently solved on the Engaging compute cluster.
    \item Post-processing: daily budgets, manual bids, and bid adjustments.
\end{enumerate}
\end{frame}

% ============================================================================
% Slide 3 — Data Processing Detail
% ============================================================================
\begin{frame}{Processing --- in more detail}
\framesubtitle{Data processing}
\begin{enumerate}
    \item Load daily keyword performance (clicks, cost) from Google Ads.
    \item Extract campaign $\to$ region mapping (USA, A, B) from campaign names.
    \item Merge with Google Keyword Planner data: search volume, competition index, bid ranges.
    \item Engineer temporal features: day-of-week, weekend, holiday, month, days to next course start.
    \item Compute search-trend features: 3-month \& 6-month averages, month-over-month change, trend slope.
    \item Generate 50-d keyword embeddings via BERT + TruncatedSVD.
    \item Impute missing values at multiple stages:
    \begin{itemize}
        \item On load: fill missing clicks/cost with 0; drop rows with unparseable dates.
        \item Before GKP merge: fill numeric nulls with 0, categorical with ``Missing''.
        \item After GKP merge: fuzzy-match keywords to fill remaining GKP gaps (search volume, trends).
        \item Final cleanup: drop any remaining rows with NaNs.
    \end{itemize}
    \item Remove outliers, train/test split.
\end{enumerate}
\end{frame}

% ============================================================================
% Slide 4 — Modeling
% ============================================================================
\begin{frame}{Processing --- in more detail}
\framesubtitle{Modeling}
\begin{itemize}
    \item Target: daily clicks per (keyword, match type, region) combination.
    \item XGBoost regressor (MSE loss) with StandardScaler + OneHotEncoder preprocessing.
    \item Hyperparameters tuned via 5-fold cross-validated grid search over:
    \begin{itemize}
        \item \texttt{n\_estimators} $\in \{5, 10, 20\}$,\; \texttt{max\_depth} $\in \{2, 3, 4\}$,\; \texttt{learning\_rate} $\in \{0.1, 0.3\}$.
    \end{itemize}
    \item Features include keyword embeddings, search stats, temporal, competitiveness, match type, region, and \textbf{cost} (the decision variable).
    \item Model interpretability: SHAP values confirm cost, search volume, and days-to-start are top drivers.
\end{itemize}
\end{frame}

% ============================================================================
% Slide 5 — Optimization Formulation (Max Clicks)
% ============================================================================
\begin{frame}{Processing --- in more detail}
\framesubtitle{Optimization --- maximize clicks}

\footnotesize

\textbf{Decision variables.}
\begin{itemize}
    \item $x_i \geq 0$: daily cost (spend) for combination $i$.
    \item $\hat{g}_i$: predicted clicks from the embedded XGBoost model for combination $i$.
    \item $B_r \geq 0$: regional sub-budget for region $r$.
\end{itemize}

\medskip
\textbf{Formulation:}
\begin{align*}
    \max_{x,\hat{g}, B_r} \quad & \sum_{i} \hat{g}_i \\
    \text{s.t.} \quad
    & \hat{g}_i = f_{\text{XGB}}(x_i, \mathbf{w}_i) && \forall\; i \\
    & \sum_{r \in \mathcal{R}} B_r = B && \text{(total budget)} \\
    & \sum_{i \in \mathcal{I}_r} x_i \leq B_r && \forall\; r \in \mathcal{R} \\
    & \hat{g}_i - \hat{g}_i^{(0)} \leq S_i && \forall\; i \text{ with exact match} \\
    & B_{\text{USA}} \geq B_{\text{A}} \geq B_{\text{B}} && \text{(optional)} \\
    & x_i \geq 0,\; \hat{g}_i \geq 0 && \forall\; i
\end{align*}

where $\mathbf{w}_i$ are the static features, $B$ is the total daily budget, $B_r$ is the regional sub-budget, $\mathcal{I}_r$ is the set of combinations in region $r$, $\hat{g}_i^{(0)}$ is predicted clicks at cost 0, and $S_i$ is the historical monthly search volume.

\end{frame}

% ============================================================================
% Slide 6 — Optimization Formulation (Max Purchases)
% ============================================================================
\begin{frame}{Processing --- in more detail}
\framesubtitle{Optimization --- maximize purchases}

If maximizing expected purchases instead of clicks, the objective changes to:
\begin{align*}
    \max_{x,\hat{g}, B_r} \quad & \sum_{r \in \mathcal{R}} \sum_{i \in \mathcal{I}_r} \hat{g}_i \cdot p_r
\end{align*}
where $p_r = \dfrac{\text{total purchases in region } r}{\text{total clicks in region } r}$ is the historical purchase rate for region $r$.

\medskip
All other constraints remain the same.

\medskip
\textbf{XGBoost embedding.} Each tree is linearized: for each row $i$ and tree $t$, binary indicator variables $z_{i,t,\ell}$ select exactly one leaf. Static feature splits are pruned at build time; the cost variable splits become Big-M constraints on $x_i$, giving a mixed-integer program solvable by Gurobi.
\end{frame}

\begin{frame}{Implementation}
\framesubtitle{Uploading solution to Google Ads}

The following should be uploaded daily to Google Ads (e.g., through API):

\begin{enumerate}
    \item Separate each match type and region into campaigns, and have a daily budget for each campaign. E.g., USA + Exact match, USA + Phrase match, etc.
    \item Base bid for each $i$ (keyword, match type, region combination).
        \begin{itemize}
            \item Calculated as $\dfrac{\text{daily cost}_i}{\text{predicted clicks}_i} \times 1.3$
            \item $\times 1.3$ is because we pay less than what we bid due to the second-price auction mechanism. This value will need to be validated experimentally.
        \end{itemize}
    \item Bid adjustments for hour of the day and the user.
        \begin{itemize}
            \item Based on purchase rates $\left(\dfrac{\text{num purchases}}{\text{num clicks}}\right)$.
            \item Calculated as $\dfrac{\text{segment purch rate}}{\text{region purch rate}} - 1$.
            \item Input to Google Ads as percentage adjustments to the base bid (e.g., +30\%, -50\%).
        \end{itemize}
\end{enumerate}
\end{frame}
